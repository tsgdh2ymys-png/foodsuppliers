# FoodSuppliers — поиск и сравнение поставщиков продуктов питания

Веб-сервис, который помогает закупщику food-бизнеса быстро находить поставщиков
(ингредиенты, готовая продукция, упаковка и др.), собирать по ним ключевую информацию
в едином виде и сравнивать, с кем выгоднее связаться.

**Демо:** _ссылка на Render появится после деплоя_
**Репозиторий:** https://github.com/tsgdh2ymys-png/foodsuppliers

> Часть 2 тестового задания. Цель — показать продуктовую идею, логику работы и рабочий прототип.

---

## Проблема и идея

Закупщик ищет поставщиков по десяткам сайтов, чатов и выставок: информация разрозненная,
в разных форматах — тяжело сравнить и понять, кому написать первым. Существующие B2B-каталоги
работают как «жёлтые страницы»: много шума, нет удобного сравнения.

**Идея сервиса** — не очередной каталог, а **инструмент принятия решения**: единые карточки
поставщиков + сравнение ключевых параметров бок о бок под задачу конкретного закупщика.

---

## Соответствие ТЗ

| Требование ТЗ | Как реализовано |
|---|---|
| Поиск по категории товара | Фильтр по категории + полнотекстовый поиск (название, описание, город, регион) |
| Учитывать город / регион | Фильтр по городу; регион работы — в поиске и в карточке |
| Собирать основную информацию | Единые карточки поставщиков |
| Контакты, сайт или источник | Телефон, e-mail, сайт + ссылка на первоисточник у реальных |
| Помогать принять решение | Страница сравнения 2–4 поставщиков бок о бок |
| Доп. данные | Мин. заказ, цена, документы/сертификаты, доставка, регион работы, комментарий, заметки |

**Сверх ТЗ:** фильтр «реальные / тестовые данные», избранное, личные заметки, добавление своего поставщика.

---

## Как это работает

1. **Каталог.** Фильтры (категория, город, тип данных) + поиск. На карточке — ключевая информация
   и бейдж источника данных.
2. **Карточка поставщика.** Все детали: контакты, сайт, источник, мин. заказ, цена, документы,
   доставка, комментарий. Можно добавить в избранное и оставить личную заметку.
3. **Сравнение.** Отмечаешь 2–4 поставщиков чекбоксом → таблица бок о бок по всем параметрам →
   видны отличия, легко решить, с кем связаться.

## Данные

**42 поставщика в 12 категориях: 28 реальных + 14 тестовых.**

- **Реальные** (бейдж «● реальный») — найдены веб-поиском, у каждого есть **ссылка на сайт-источник**.
  Категории: ингредиенты, упаковка, бакалея/специи, молочная продукция, замороженные, готовая
  продукция, напитки, мясо и птица, овощи и фрукты, рыба и морепродукты, хлебобулочные/выпечка,
  мультикатегорийные дистрибьюторы HoReCa. Города: Москва, СПб, Екатеринбург, Краснодар,
  Новосибирск, Казань, Ростов-на-Дону.
- **Тестовые** (бейдж «⚙ тестовый») — синтетические карточки с полностью заполненными полями
  (включая числа), чтобы наглядно показать сравнение во всех категориях.

**Честность данных.** У реальных B2B-поставщиков цена/мин. заказ/часть документов закрыты
(«по запросу») — в таких полях стоит «нет данных», значения **не выдумываются**. База создаётся
и наполняется автоматически при первом запуске.

## Технологии и почему так

| Слой | Стек | Почему |
|---|---|---|
| Backend | FastAPI | быстрый старт, типизация, понятные роуты |
| Шаблоны | Jinja2 (SSR) | без отдельного фронтенд-билда |
| Вёрстка | Tailwind (CDN) | аккуратный вид без шага сборки |
| Хранилище | SQLite + SQLAlchemy | ноль конфигурации; переезд на PostgreSQL — одной переменной `DATABASE_URL`, без правок кода |
| Хостинг | Render (free) | постоянный веб-сервис, SQLite работает «из коробки» |

Принцип: самый лёгкий инструмент под задачу, без оверинжиниринга; при этом архитектура расширяема
(слой данных и шаблоны разделены, БД абстрагирована за `DATABASE_URL`).

```
app/
├── main.py        # роуты FastAPI (каталог, карточка, избранное, заметки, сравнение, добавление)
├── database.py    # подключение к БД (SQLite → Postgres через DATABASE_URL)
├── models.py      # модель Supplier
├── seed_data.py   # реальные (найденные) + тестовые данные и комментарии
├── templates/     # base, index, supplier, compare, add
└── static/app.js  # выбор поставщиков для сравнения
```

## Принятые решения (и почему)

- **Сравнение вместо «скоринга».** Была версия со взвешенными баллами 0–100 и слайдерами важности.
  От неё отказались: при сравнении 2–3 поставщиков относительные баллы вводили в заблуждение
  (худшее значение в наборе показывалось как «0», будто данных нет), а итоговый балл выглядел как
  ложная точность. Прозрачная таблица сравнения — честнее и понятнее.
- **Честные пробелы.** «Нет данных» вместо выдуманных цифр.
- **Без авторизации** (осознанное упрощение под прототип): избранное и заметки — общие.

## Как можно улучшить в дальнейшем

- **Авторизация и личные данные** — личные списки/заметки на пользователя, командная работа отдела закупок.
- **Взвешенное ранжирование** под приоритеты закупки — когда по поставщикам будет больше сопоставимых данных.
- **Справочник регионов** — нормализованный, с отдельным фильтром по региону (сейчас регион — свободный текст).
- **Пагинация и серверный поиск** — при росте базы до сотен поставщиков.
- **Запрос КП из карточки** — кнопка «отправить запрос» поставщику + история обращений.
- **Автозаполнение данных** — импорт/парсинг каталогов вместо ручного ввода.
- **Тесты и CI** — pytest на фильтры и сборку данных, автопрогон в CI.
